# 简约轻量级 HTML-PPT 设计规范与提炼指引

本参考手册用于指导 Agent 在理解用户的文字草稿、截图或初稿时，如何进行高质量的**内容重构、信息看板化与视觉呈现**。

---

## 一、文案理解与结构化重构原则

当拿到用户的原始资料（散文、Bullet Points、表格截图、沟通记录）时，严禁“全文照搬贴进卡片”。必须进行以下三层提炼：

### 1. 战略与摘要层（Header）
* **大标题 (H1)**：8 ~ 18 个汉字，高度概括业务核心与行动方向（例如：`业务方向聚焦与落地攻坚 · AI 工程化探索沉淀`）。
* **一句话副标 (Subtitle)**：解释本页 PPT 的业务上下文、核心价值与演进态势（例如：`围绕核心业务场景打通可用性闭环与体验规范；持续推进 AI 从原型验证到工具链演进`）。
* **分类与周期角标**：`MID-YEAR REVIEW`、`2024 上半年度工作复盘` 等。

### 2. 量化看板层（Metrics Strip）
领导与听众最先扫视的是**数字化指标**。任何包含数字、量级、周期的内容，必须提取为 Metric Box：
* **数字 (Value)**：字号 `20~24px`，加粗，使用无衬线科技字体（如 `Plus Jakarta Sans`）。
  * 示例：`900+`、`70%`、`100%`、`80%~90%`、`9+`
* **标签 (Label)**：字号 `12~13px`，灰色文字。
  * 示例：`自检/演示检视问题`、`整体闭环率`、`核心体验缺陷解决`

### 3. 结构化卡片层（Cards & Bullets）
* **卡片分类**：根据内容逻辑拆解为 2 栏（58% 业务 : 42% AI/赋能）或 3 栏（方案A / 方案B / 方案C）。
* **状态胶囊 (Status Badges)**：
  * 延期/调整：浅黄底 + 焦糖字（`#FEF3C7` / `#92400E`）→ 如 `预计 10.16 预发布`
  * 正常推进/里程碑：浅蓝底 + 宝蓝字（`#EFF6FF` / `#1E40AF`）→ 如 `国庆后 Beta`、`TR1 评审通过`
  * 审慎/观察：浅灰底 + 铁灰字（`#F1F5F9` / `#475569`）→ 如 `审慎投入 · 保持观察`
  * 技能/能力：浅紫底 + 靛蓝字（`#EEF2FF` / `#4F46E5`）→ 如 `标准 Token 体系`
* **痛点/成果粗体标注**：卡片内的每一段内容，前 4~8 个字必须加粗作为导读锚点（例如：`<strong class="highlight-text">高保真业务 Demo 与可用性闭环</strong>：...`）。

## 二、严格 16:9 物理画板自适应规范

1. **画布基准尺寸**：
   * 采用固定的 `1920px × 1080px` 物理尺寸。
2. **居中与缩放算法**：
   * 使用绝对定位居中：`position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%) scale(var(--slide-scale));`
   * 缩放比例由 JS 动态计算：
     ```javascript
     const marginRatio = isFullscreen ? 0.98 : 0.94;
     const scale = Math.min((window.innerWidth * marginRatio) / 1920, (window.innerHeight * marginRatio) / 1080);
     ```
   * 这种算法能保证在任意分辨率（不论视口是高是矮、是宽是窄）下，幻灯片永远保持 16:9 完整呈现在视口中央，绝对不产生滚动条，内容永不截断。

---

## 三、交付与格式约束

1. **输出物要求**：
   * 输出标准的 `.html` 格式文件（如 `xxx_slide.html`）。
   * 同步输出一张配套的 16:9 高清大图（如 `xxx_slide.png`）。
2. **导出功能集成**：
   * HTML 文件底部常驻磨砂质感控制坞，包含 `全屏演示`、`导出 PDF`（调用系统打印流）与 `下载高清图片`。
3. **PPTX 文件生成策略**：
   * **除非用户在 prompt 中明确指明要生成 PPT/PPTX 文件，否则不主动生成 `.pptx`**。
   * 用户主要通过网页演示或直接复制 PNG 大图到自己的汇报中，免去 Office 排版错乱的困扰。
